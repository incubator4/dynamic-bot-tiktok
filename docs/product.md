# 产品：抖音来源插件

## 一句话

让 dynamic-bot 能订阅抖音用户，把新作品渲染并推送到已配置的消息出口（例如 QQ / OneBot）。

本仓库只交付 **一个** 内容来源插件的 fatJar。登录、轮询、发布者资料、作品映射、链接解析都发生在这个插件里；订阅关系、绘图、投递、重试、撤回由主程序负责。

## 用户能做什么

1. 在 Web 后台启用本插件，用抖音 Cookie 或扫码完成登录。
2. 用抖音用户 ID 添加发布者，并绑到已有消息目标。
3. 插件检测到新作品后，交给主程序推送。
4. 订阅开启直播事件后，插件检测到开播 / 下播，交给主程序推送。
5. （一期宜做）聊天里出现抖音链接时，解析成预览或动态卡片。

## 一期（MVP）

必须有：

- Cookie / 扫码登录与登录态检查；未登录 / 风控时暂停轮询。
- 按用户 ID 查询发布者资料（昵称、头像、主页）。
- 轮询已订阅用户的新作品（视频 / 图集都映射成动态）。
- 轮询已订阅直播事件的用户，发布开播 / 下播（`LivePayload`），启动不把已在播当成新开播。
- 用 `DynamicPayload.blocks` 按平台原始展示顺序建模。
- 游标去重：启动默认不补发旧作品。
- 插件配置表单（中文）：轮询开关、轮询间隔、请求间隔、补发窗口、直播检测开关、未登录暂停阈值。

应该有：

- 解析 `douyin.com` 作品 / 用户主页，并尽量补上作者和封面；`v.douyin.com` 短链无法展开时返回中文错误（见 ADR-0011）。

## 明确不做（一期）

- 不当主程序，不实现 `MessageSinkPlugin`。
- 不把订阅列表、消息目标、绘图主题做进本插件。
- 不默认做用户名搜索、自动关注、视频无水印下载、直播流/弹幕。
- 不覆盖国际版 TikTok（`tiktok.com`）。
- 不打包独立可运行 Bot，不引入第二套命令或投递通道。
- 不提交 Cookie、抓包会话或绕过平台风控的实现说明。

后续能力（搜索、关注、视频下载、国际版 TikTok）只有在对应 ADR 被接受后才开工。直播开播/下播见 ADR-0009；扫码登录见 ADR-0010。

## 使用约束

抖音接口比一般资讯源更敏感。默认策略对齐微博 / 小红书插件：轮询可默认关闭或间隔偏长；连续请求必须留间隔；登录失效立即停手，而不是加大重试。
